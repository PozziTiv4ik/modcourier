# ModCourier

**Один мод, две площадки, понятный маршрут для ИИ-агента.**

ModCourier помогает опубликовать Minecraft Java мод на **Modrinth** и
**CurseForge**. Читает готовые JAR, проверяет существующие проекты и версии,
загружает недостающее и сохраняет результат каждого шага.

## Самый простой способ

Дай агенту ссылку на этот репозиторий и напиши:

> Мод готов. Прочитай https://github.com/PozziTiv4ik/modcourier и опубликуй его на Modrinth и CurseForge.

Агент начинает с [AGENTS.md](AGENTS.md). Он использует папку мода из текущего
чата, проверяет сборку и публикации, заполняет конфигурацию и запускает команды.
Если неизвестен конкретный мод или отсутствует доступ, выясняет именно это.

Нужен **Python 3.11+**. Установка дополнительных Python-пакетов не требуется.
Можно скачать один файл `modcourier.pyz` из
[Releases](https://github.com/PozziTiv4ik/modcourier/releases) или запустить
`modcourier.py` прямо из клонированного репозитория.

## Если запускать вручную

Сначала собери свой мод обычной командой его проекта. Затем:

```powershell
python D:\Tools\modcourier.pyz init --project D:\Mods\MyMod
python D:\Tools\modcourier.pyz inspect --project D:\Mods\MyMod --json
python D:\Tools\modcourier.pyz publish --project D:\Mods\MyMod --dry-run
python D:\Tools\modcourier.pyz publish --project D:\Mods\MyMod
python D:\Tools\modcourier.pyz status --project D:\Mods\MyMod
```

`init` создаёт `modcourier.json` по метаданным JAR. Агент дополняет то, что
невозможно честно угадать: проверенные версии Minecraft, поведение на клиенте
и сервере, описание изменений, категории, зависимости и сведения об использовании ИИ.
Версия самого мода берётся из собранного файла.

## Что происходит автоматически

| Ситуация | Действие |
|---|---|
| Проект найден, версия новая | Загрузка нового релиза |
| Точно такой же файл уже есть | Пропуск |
| Проект есть на одной площадке | Отдельный план для второй |
| Одна загрузка завершилась, другая упала | Продолжение незавершённой |
| Сервер мог принять файл до обрыва связи | Проверка результата перед повтором |
| Название совпало, принадлежность неясна | Проверка владельца и привязка ID |
| Старый номер версии, другое содержимое | Сообщение о конфликте |

Поддерживаются Fabric, Forge, NeoForge, Quilt и несколько вариантов одного
релиза. Исходники, dev-JAR и смешанные старые сборки не отправляются по ошибке.

## Первый проект и доступы

На Modrinth создание проекта доступно через API. Для новой страницы CurseForge
понадобится авторский сайт: ModCourier подготовит данные и инструкцию, а агент
с управлением браузером сможет выполнить этот шаг в твоём аккаунте.
Если у агента нет браузера, подготовленный шаг выполняет человек.

У CurseForge **разные ключи для загрузки и чтения каталога**. Они не
взаимозаменяемы. Без ключа каталога существующие публикации проверяют через
авторский кабинет; отсутствие доступа не считается отсутствием мода.

Секреты задаются локально через `MODRINTH_TOKEN`, `CURSEFORGE_UPLOAD_TOKEN`
и `CURSEFORGE_API_KEY`. В репозиторий или сообщения их вставлять не нужно.
Подробности — [настройка](docs/setup.md).

Modrinth ограничивает преимущественно сгенерированные ИИ проекты и требует
определённых раскрытий при существенном использовании ИИ. Агент учитывает
реальное происхождение мода и материала страницы.

## Где лежит результат

- `modcourier.json` — настройки и ID площадок; можно хранить в Git.
- `.modcourier/state.json` — журнал, нужный для продолжения после сбоя.
- `.modcourier/report.json` — результаты последней публикации.
- `.modcourier/handoff.md` — конкретные действия в браузере, если они понадобились.

Папка `.modcourier/` исключается из Git. Сохранённый журнал нельзя удалять,
чтобы «починить» неизвестный результат загрузки: для этого есть
[восстановление](docs/recovery.md).

Принято сервером, ожидает модерации и опубликовано — разные статусы.
Инструмент показывает тот статус, который удалось проверить.
